# Omarchy tool and workflow ideas

Research date: 2026-08-30. Sources are the [official Omarchy manual](https://omarchy.org/manual/) and its [source repository](https://github.com/omacom/omarchy).

| Idea                                            | Fedora KDE Plasma use                                                                                                                                                                                  | Evidence                                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `mise` for language runtimes                    | Candidate for the shared developer core. It manages versions for many language environments. ## Suitable workflow patterns

- Use a small default profile and opt-in capability packs. Omarchy separates editor, terminal, development, and service installation choices in its menu. [Development Tools](https://omarchy.org/manual/development-tools/)
- Separate user configuration from reviewed system configuration. Omarchy documents root-side setup and later per-user provisioning as different operations. Dotfiles v2 should keep this split, with a strict sudo allow-list. [File layout](https://github.com/omacom/omarchy/blob/quattro/docs/file-layout.md)
- Make runs repeatable and keep explicit completion state or checks. Omarchy records a per-user finalization marker; Dotfiles v2 should instead expose idempotent checks that work in fresh VMs. [File layout](https://github.com/omacom/omarchy/blob/quattro/docs/file-layout.md)
- Make security choices visible. Docker group access, firewall openings, and similar system changes must be explicit profile decisions. [Development Tools](https://omarchy.org/manual/development-tools/)
- Consider a default-deny firewall and explicit SSH activation as Fedora-specific security decisions; do not import Omarchy firewall scripts. [Security](https://omarchy.org/manual/security/)

## Do not copy into Fedora KDE Plasma

| Omarchy part                                                           | Reason                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Omarchy as an installation base                                        | It is an Arch Linux distribution built around Hyprland and Quickshell, not Fedora KDE Plasma. [Manual introduction](https://omarchy.org/manual/)                                                                                                                |
| `omarchy` CLI, menu, package commands, and AUR workflow                | These commands implement Omarchy and Arch package management. Dotfiles v2 needs its own Fedora package and configuration layer. [Other Packages](https://omarchy.org/manual/other-packages/)                                                                    |
| Hyprland, Quickshell, Omarchy hotkeys, bar, launcher, and theme wiring | These form its opinionated tiling desktop. KDE Plasma needs native configuration and separate usability decisions. [Manual introduction](https://omarchy.org/manual/)                                                                                           |
| Omarchy system defaults, ISO installer, and resync mechanism           | They write Arch package-owned files and can overwrite user configuration. Dotfiles v2 must use narrow, owned paths and preserve its v1 setup until the migration gate passes. [File layout](https://github.com/omacom/omarchy/blob/quattro/docs/file-layout.md) |
| Hyprland-only Wayland utilities                                        | `hyprland`, `hyprpicker`, `hyprsunset`, `grim`, `slurp`, `wl-clipboard`, `wtype`, `uwsm`, and `xdg-desktop-portal-hyprland` belong to the Hyprland stack. Select KDE-native replacements only when a later ticket specifies the required behavior.              | [Omarchy base packages](https://github.com/omacom/omarchy/blob/quattro/install/omarchy-base.packages) |

## Profile-selection input

Start the Fedora profile discussion with: terminal choice, editor choice, `mise`, the shell-tool trial set, Tmux, Git TUI, Docker capability, and LocalSend. Treat all other Omarchy desktop applications as later optional application packs.
